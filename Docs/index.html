Современный OpenGL на C# и Silk.NET

Практический курс о том, как устроить рендерер, а не только нарисовать треугольник. Мы последовательно соберём окно, ресурсную модель, материалы, PBR, тени, HDR, bloom, deferred pipeline, compute-задачи и систему постобработки.

Что именно делает OpenGL

OpenGL — не движок и не библиотека сцены. Это API к машине состояний драйвера. Вы создаёте GPU-ресурсы, связываете их с точками привязки, настраиваете pipeline и отправляете команды рисования. Silk.NET предоставляет быстрые C# bindings: имена и семантика почти один в один соответствуют C API.

CPU scene→command setup→vertex shader→rasterizer→fragment shader→framebuffer
Объект

Имя GPU-ресурса: buffer, texture, shader, program, framebuffer. В C# это обычно uint.

Binding

Выбор объекта, к которому относятся следующие команды. Современный DSA API часто позволяет обходиться без bind.

State

Depth test, blending, viewport, culling и текущая программа сохраняются в контексте.

Draw call

Команда, интерпретирующая текущие состояния и буферы как примитивы.

Выбранный baselineПримеры ориентированы на OpenGL 4.5 Core и Direct State Access. Для macOS максимум обычно OpenGL 4.1 — DSA-вызовы придётся заменить bind-based эквивалентами.

Окно, события и render loop

Контекст должен существовать до вызова GL.GetApi(window). Поэтому все GL-ресурсы создавайте в обработчике Load, рисуйте в Render, меняйте симуляцию в Update, освобождайте в Closing.

Program.cs
using Silk.NET.Maths;
using Silk.NET.OpenGL;
using Silk.NET.Windowing;

var options = WindowOptions.Default;
options.Title = "Graphics Lab";
options.Size = new Vector2D<int>(1280, 720);
options.API = new GraphicsAPI(
    ContextAPI.OpenGL,
    ContextProfile.Core,
    ContextFlags.Debug,
    new APIVersion(4, 5));
options.VSync = true;

using var window = Window.Create(options);
GL gl = null!;

window.Load += () =>
{
    gl = GL.GetApi(window);
    gl.Enable(EnableCap.DepthTest);
    gl.Enable(EnableCap.CullFace);
    gl.CullFace(TriangleFace.Back);
};

window.FramebufferResize += size =>
    gl.Viewport(0, 0, (uint)size.X, (uint)size.Y);

window.Update += dt =>
{
    // Fixed-step physics лучше запускать отдельным accumulator.
};

window.Render += dt =>
{
    gl.ClearColor(0.025f, 0.035f, 0.055f, 1f);
    gl.Clear(ClearBufferMask.ColorBufferBit |
             ClearBufferMask.DepthBufferBit);
};

window.Closing += () => gl?.Dispose();
window.Run();
Размер окна ≠ размер framebufferНа HiDPI-дисплеях framebuffer может быть больше логического окна. Для Viewport, aspect ratio и render targets используйте именно framebuffer size.

Потоки и контекст

OpenGL-контекст активен на одном потоке. Не вызывайте GL из asset-loader task. Фоновый поток может читать и декодировать файлы, но создание texture/buffer следует поставить в очередь команд render thread. Shared contexts возможны, однако усложняют синхронизацию и редко нужны в первом рендерере.

GraphicsDevice как граница OpenGL

GraphicsDevice владеет экземпляром GL, знает возможности адаптера и остаётся единственной точкой низкоуровневых вызовов. Он создаётся после window.Load и уничтожается до контекста.

GraphicsDevice.cs · C#
public sealed class GraphicsDevice : IDisposable
{
    public GL GL { get; }
    public string Vendor { get; }
    public string Renderer { get; }

    public GraphicsDevice(IWindow window)
    {
        GL = GL.GetApi(window);
        Vendor = GL.GetStringS(StringName.Vendor);
        Renderer = GL.GetStringS(StringName.Renderer);
        GlDebug.Enable(GL);
    }

    public void SetViewport(int width, int height) =>
        GL.Viewport(0, 0, (uint)width, (uint)height);

    public void Dispose() => GL.Dispose();
}

Очистка экрана

Color, depth и stencil очищаются независимо. Делайте это после привязки нужного framebuffer и установки viewport.

Debug output до первой ошибки

gl.GetError() плохо локализует проблему и синхронизирует CPU с драйвером. В debug-сборке подключите callback KHR_debug и ставьте осмысленные labels объектам.

GlDebug.cs
using Silk.NET.OpenGL;
using System.Runtime.InteropServices;

static unsafe class GlDebug
{
    private static readonly DebugProc CallbackDelegate = OnMessage;

    public static void Enable(GL gl)
    {
        gl.Enable(EnableCap.DebugOutput);
        gl.Enable(EnableCap.DebugOutputSynchronous);
        gl.DebugMessageCallback(CallbackDelegate, null);
        gl.DebugMessageControl(
            DebugSource.DontCare, DebugType.DontCare,
            DebugSeverity.DontCare, 0, null, true);
    }

    private static unsafe void OnMessage(
        GLEnum source, GLEnum type, int id, GLEnum severity,
        int length, nint message, nint userParam)
    {
        var text = Marshal.PtrToStringAnsi(message, length);
        if (severity != GLEnum.DebugSeverityNotification)
            Console.Error.WriteLine($"GL [{severity}] {id}: {text}");
    }
}

Игнорируйте только конкретные известные notification ID, а не целые категории. Маркируйте ресурсы через ObjectLabel и кадры через PushDebugGroup/PopDebugGroup — RenderDoc покажет эти имена.

Надёжная шейдерная система

Shader object — компиляция одной стадии. Program — связанный executable из нескольких стадий. Всегда проверяйте и compile status, и link status; warning log полезен даже при успехе.

ShaderProgram.cs — ядро
public sealed class ShaderProgram : IDisposable
{
    private readonly GL _gl;
    public uint Handle { get; }

    public ShaderProgram(GL gl, string vertex, string fragment)
    {
        _gl = gl;
        uint vs = Compile(ShaderType.VertexShader, vertex);
        uint fs = Compile(ShaderType.FragmentShader, fragment);
        Handle = gl.CreateProgram();
        gl.AttachShader(Handle, vs);
        gl.AttachShader(Handle, fs);
        gl.LinkProgram(Handle);
        gl.GetProgram(Handle, ProgramPropertyARB.LinkStatus, out int ok);
        string log = gl.GetProgramInfoLog(Handle);
        gl.DetachShader(Handle, vs);
        gl.DetachShader(Handle, fs);
        gl.DeleteShader(vs);
        gl.DeleteShader(fs);
        if (ok == 0) throw new InvalidOperationException($"Link failed:\n{log}");
    }

    private uint Compile(ShaderType stage, string source)
    {
        uint shader = _gl.CreateShader(stage);
        _gl.ShaderSource(shader, source);
        _gl.CompileShader(shader);
        _gl.GetShader(shader, ShaderParameterName.CompileStatus, out int ok);
        string log = _gl.GetShaderInfoLog(shader);
        if (ok == 0)
        {
            _gl.DeleteShader(shader);
            throw new InvalidOperationException($"{stage} failed:\n{log}");
        }
        return shader;
    }

    public void Use() => _gl.UseProgram(Handle);
    public void Dispose() => _gl.DeleteProgram(Handle);
}

Includes, defines и hot reload

GLSL не имеет переносимого #include. Сделайте препроцессор: нормализуйте путь, обнаруживайте циклы, вставляйте #line, собирайте dependency list. При изменении файла компилируйте новую программу целиком и заменяйте старую только после успешного link. Никогда не уничтожайте рабочий shader из-за ошибки hot reload.

Стабильный контрактЗакрепляйте locations через layout(location=N), binding points через layout(binding=N). Тогда C# и GLSL согласуются без вызовов поиска по строкам в каждом кадре.

VAO, VBO, EBO и layout

05. VertexBuffer

Owning wrapper над GL buffer хранит handle, byte size и usage. Он принимает unmanaged data и удаляет handle через тот же device.

06. VertexLayout

Layout декларативно описывает location, component count, type, normalization, stride и offset каждого атрибута.

07. VertexArray

VAO связывает layout с vertex streams. Он хранит конфигурацию чтения, но не владеет самими vertex data.

VertexBuffer + VertexLayout + VertexArray · C#
public readonly record struct VertexElement(
    uint Location, int Count, VertexAttribType Type,
    bool Normalized, uint Offset);

public sealed record VertexLayout(uint Stride, params VertexElement[] Elements);

public sealed class VertexBuffer : IDisposable
{
    private readonly GL _gl;
    public uint Handle { get; }
    public nuint Size { get; }

    public unsafe VertexBuffer<T>(GL gl, ReadOnlySpan<T> vertices)
        where T : unmanaged
    {
        _gl = gl;
        Handle = gl.CreateBuffer();
        Size = (nuint)(vertices.Length * sizeof(T));
        fixed (T* data = vertices)
            gl.NamedBufferStorage(Handle, Size, data, 0);
    }

    public void Dispose() => _gl.DeleteBuffer(Handle);
}

public static uint CreateVertexArray(
    GL gl, uint vertexBuffer, VertexLayout layout)
{
    uint vao = gl.CreateVertexArray();
    gl.VertexArrayVertexBuffer(vao, 0, vertexBuffer, 0, layout.Stride);
    foreach (VertexElement e in layout.Elements)
    {
        gl.EnableVertexArrayAttrib(vao, e.Location);
        gl.VertexArrayAttribFormat(
            vao, e.Location, e.Count, e.Type, e.Normalized, e.Offset);
        gl.VertexArrayAttribBinding(vao, e.Location, 0);
    }
    return vao;
}
Как это читается GPUПри draw GPU берёт номер vertex, прибавляет baseOffset + index × stride + attributeOffset и интерпретирует найденные байты согласно типу элемента. VAO сохраняет именно эту формулу.

Для indexed mesh используйте DrawElements. Тип индекса обязан совпадать с upload: ushort → UnsignedShort, uint → UnsignedInt. Последний аргумент — byte offset внутри EBO, а не managed pointer.

09. IndexBuffer

IndexBuffer должен помнить количество и тип индекса, чтобы renderer не смог неверно интерпретировать GPU-память.

10. Квадрат

Квадрат использует четыре вершины и шесть индексов: [0, 1, 2, 2, 3, 0]. Это первая проверка winding и DrawElements.

IndexBuffer и квадрат · C#
uint[] indices = [0, 1, 2, 2, 3, 0];
uint ebo = gl.CreateBuffer();
unsafe
{
    fixed (uint* data = indices)
        gl.NamedBufferStorage(
            ebo, (nuint)(indices.Length * sizeof(uint)), data, 0);
}

// EBO binding является частью состояния VAO.
gl.VertexArrayElementBuffer(vao, ebo);
gl.BindVertexArray(vao);

    PrimitiveType.Triangles,
    (uint)indices.Length,
    DrawElementsType.UnsignedInt,
    null);

Interleaved или separate

Interleaved layout удобен и кэш-дружественен, когда все атрибуты используются вместе. Separate streams полезны для редкого обновления одного атрибута и для разных shader layouts. Не полагайтесь слепо на размер C# struct: проверьте Unsafe.SizeOf<Vertex>() и используйте sequential layout/unmanaged fields.

Uniform, UBO, SSBO и alignment

Одиночные uniform подходят для редких параметров. Камеру и frame data лучше хранить в UBO, чтобы один buffer binding обслуживал множество программ.

GLSL + C# UBO
// GLSL
layout(std140, binding = 0) uniform CameraData {
    mat4 uView;
    mat4 uProjection;
    mat4 uViewProjection;
    vec4 uCameraPosition; // vec4 упрощает alignment
};

// C#
uint cameraUbo = gl.CreateBuffer();
gl.NamedBufferStorage(cameraUbo, (nuint)Unsafe.SizeOf<GpuCamera>(),
    null, BufferStorageMask.DynamicStorageBit);
gl.BindBufferBase(BufferTargetARB.UniformBuffer, 0, cameraUbo);

unsafe
{
    GpuCamera data = BuildCamera();
    gl.NamedBufferSubData(cameraUbo, 0,
        (nuint)Unsafe.SizeOf<GpuCamera>(), &data);
}
std140 paddingvec3 часто занимает слот в 16 байт; массивы и структуры имеют дополнительное выравнивание. На CPU предпочитайте vec4 и явно проверяйте offsets reflection-инструментом. Матрицы System.Numerics и GLSL могут требовать transpose в зависимости от принятой конвенции.

SSBO использует std430, допускает большие массивы и запись из shader. После compute/write поставьте точный MemoryBarrier перед последующим чтением.

Текстуры, color space и sampler

Texture storage, pixel upload и sampling — отдельные решения. Allocate immutable storage через TextureStorage2D, загрузите mip 0, сгенерируйте mipmaps и задайте sampler state.

Texture2D upload
using var stream = File.OpenRead(path);
var image = ImageResult.FromStream(stream, ColorComponents.RedGreenBlueAlpha);

uint texture = gl.CreateTexture(TextureTarget.Texture2D);
int levels = 1 + (int)MathF.Floor(MathF.Log2(Math.Max(image.Width, image.Height)));
gl.TextureStorage2D(texture, (uint)levels, SizedInternalFormat.Srgb8Alpha8,
    (uint)image.Width, (uint)image.Height);

unsafe
{
    fixed (byte* pixels = image.Data)
        gl.TextureSubImage2D(texture, 0, 0, 0,
            (uint)image.Width, (uint)image.Height,
            PixelFormat.Rgba, PixelType.UnsignedByte, pixels);
}

gl.GenerateTextureMipmap(texture);
gl.TextureParameter(texture, TextureParameterName.TextureMinFilter,
    (int)TextureMinFilter.LinearMipmapLinear);
gl.TextureParameter(texture, TextureParameterName.TextureMagFilter,
    (int)TextureMagFilter.Linear);
gl.TextureParameter(texture, TextureParameterName.TextureWrapS,
    (int)TextureWrapMode.Repeat);

Linear workflow

Base color/emissive изображения обычно sRGB: используйте Srgb8/Srgb8Alpha8, чтобы sampling автоматически декодировал их в linear. Normal, roughness, metallic, AO и height — данные, поэтому загружайте в linear formats. Освещение всегда считайте в linear, а кодирование результата выполняйте один раз при выводе.

Sampler object отделяет filtering/wrap от texture storage. Это удобно, если одна shadow map читается с разными compare modes или одна texture показывается в UI без mip filtering.

12. Текстурированный квадрат

Добавьте UV в layout, привяжите Texture2D к unit, а sampler uniform — к номеру unit. Перевёрнутые UV исправляйте единым соглашением importer, а не случайными инверсиями в шейдерах.

void main()
{
    vec4 texel = texture(uTexture, vUv);
    if (texel.a < 0.01) discard;

Матрицы, координаты и камера

13. Transform

Transform хранит position, quaternion rotation и scale. World matrix вычисляется с учётом parent и кэшируется до следующего изменения.

Transform.cs · C#
public sealed class Transform
{
    public Vector3 Position { get; set; }
    public Quaternion Rotation { get; set; } = Quaternion.Identity;
    public Vector3 Scale { get; set; } = Vector3.One;
    public Transform? Parent { get; set; }

    public Matrix4x4 LocalMatrix =>
        Matrix4x4.CreateScale(Scale) *
        Matrix4x4.CreateFromQuaternion(Rotation) *
        Matrix4x4.CreateTranslation(Position);

    public Matrix4x4 WorldMatrix =>
        Parent is null ? LocalMatrix : LocalMatrix * Parent.WorldMatrix;
}
Порядок зависит от соглашенияПример использует row-vector convention System.Numerics. Зафиксируйте один порядок во всём engine и выполняйте transpose только на границе загрузки в GLSL.
model/local→ Mworld→ Vview→ Pclip÷ wNDC

Vertex shader обычно вычисляет gl_Position = projection * view * model * vec4(position,1). После perspective divide NDC OpenGL имеет Z от −1 до 1, если вы не включили ClipControl. Экранное пространство появляется после viewport transform.

14. Camera

Camera matrices · C#
float aspect = framebufferWidth / (float)framebufferHeight;
Matrix4x4 view = Matrix4x4.CreateLookAt(position, position + forward, Vector3.UnitY);
Matrix4x4 projection = Matrix4x4.CreatePerspectiveFieldOfView(
    MathF.PI / 3f, aspect, 0.1f, 1000f);

// Перед upload зафиксируйте соглашение вашего math layer.
// Частый вариант для GLSL:

Не копируйте порядок из примера без теста. Нарисуйте асимметричную сцену и проверьте translation/rotation. Лучше создать единственный helper загрузки матриц и закрепить соглашение тестами.

Reverse-Z

Для больших миров полезен reverse-Z: ClipControl(LowerLeft, ZeroToOne), depth clear 0, comparison Greater, бесконечная reversed projection. Точность float depth концентрируется дальше от камеры значительно разумнее.

Не заставляйте scene object непосредственно вызывать GL. Сначала извлеките видимые render items, затем сортируйте и исполняйте. Это открывает путь к culling, batching, shadow pass и нескольким камерам.

16. Material

Material связывает shader pipeline, textures и параметры, но сам не рисует. Дайте ему стабильный sort key для группировки draw calls.

17. MeshRenderer / RenderObject

Scene-компонент ссылается на mesh/material, а extraction превращает его в плоский RenderObject с world matrix, bounds и GPU handles.

18. Renderer

Renderer принимает camera и render objects, делает culling и sorting, выбирает pipeline state и отправляет команды. Он не загружает файлы и не обновляет gameplay.

Material → RenderObject → Renderer · C#
public sealed record Material(
    ShaderProgram Shader,
    Texture2D Albedo,
    Vector4 Tint,
    bool Transparent = false);

public readonly record struct RenderObject(
    Mesh Mesh,
    Material Material,
    Matrix4x4 World,
    BoundingBox Bounds);

public void Draw(
    Camera camera,
    ReadOnlySpan<RenderObject> objects)
{
    foreach (ref readonly RenderObject item in objects)
    {
        if (!camera.Frustum.Intersects(item.Bounds, item.World))
            continue;

        item.Material.Shader.Use();
        item.Material.Shader.SetMatrix("uWorld", item.World);
        item.Material.Shader.SetMatrix("uViewProjection", camera.ViewProjection);
        item.Material.Albedo.Bind(0);
        item.Mesh.Draw();
    }
}

Следующий уровень — разделить сбор команд и исполнение. Сначала сформируйте render queue, удалите невидимое, разбейте opaque/transparent, отсортируйте opaque по shader/material, а transparent — от дальних к ближним.

Phong, normal matrix и пространство расчёта

Считайте позиции, normals, lights и camera в одном пространстве — обычно world или view. Normal нельзя преобразовывать model matrix напрямую при non-uniform scale: используйте inverse-transpose верхней 3×3 части.

Fragment lighting
vec3 N = normalize(vWorldNormal);
vec3 L = normalize(uLightPosition - vWorldPosition);
vec3 V = normalize(uCameraPosition - vWorldPosition);
vec3 H = normalize(L + V);

float NoL = max(dot(N, L), 0.0);
float specular = pow(max(dot(N, H), 0.0), uShininess);
float attenuation = 1.0 / max(dot(uAttenuation,
    vec3(1.0, distance(L), distance(L) * distance(L))), 0.0001);

vec3 color = (uAlbedo * NoL + uSpecularColor * specular)
           * uLightColor * uIntensity * attenuation;

Phong полезен для изучения, но его параметры плохо соответствуют физическим материалам. Production-пайплайн обычно переходит к microfacet BRDF.

Metallic-roughness и Cook–Torrance

PBR не означает «фотореализм автоматически». Он означает сохранение энергии и параметры, которые ведут себя устойчиво при разном освещении. glTF workflow использует base color, metallic, perceptual roughness, normal, occlusion и emissive.

PBR BRDF — компактное ядро
const float PI = 3.14159265359;

float D_GGX(float NoH, float roughness) {
    float a = roughness * roughness;
    float a2 = a * a;
    float d = NoH * NoH * (a2 - 1.0) + 1.0;
    return a2 / max(PI * d * d, 1e-6);
}

float V_SmithGGX(float NoV, float NoL, float roughness) {
    float a = roughness * roughness;
    float gv = NoL * sqrt(NoV * NoV * (1.0 - a) + a);
    float gl = NoV * sqrt(NoL * NoL * (1.0 - a) + a);
    return 0.5 / max(gv + gl, 1e-6);
}

vec3 F_Schlick(float VoH, vec3 F0) {
    return F0 + (1.0 - F0) * pow(1.0 - VoH, 5.0);
}

vec3 EvaluateBRDF(vec3 N, vec3 V, vec3 L,
                  vec3 baseColor, float metallic, float roughness) {
    vec3 H = normalize(V + L);
    float NoV = max(dot(N, V), 1e-4);
    float NoL = max(dot(N, L), 0.0);
    float NoH = max(dot(N, H), 0.0);
    float VoH = max(dot(V, H), 0.0);
    roughness = max(roughness, 0.045);
    vec3 F0 = mix(vec3(0.04), baseColor, metallic);
    vec3 F = F_Schlick(VoH, F0);
    vec3 spec = D_GGX(NoH, roughness)
              * V_SmithGGX(NoV, NoL, roughness) * F;
    vec3 diffuse = (1.0 - F) * (1.0 - metallic) * baseColor / PI;
    return (diffuse + spec) * NoL;
}

Light intensity и HDR buffer должны позволять значения выше 1.0. Tone mapping выполняется позже. Normal map преобразуется из tangent space через TBN; tangent handedness храните в tangent.w.

Shadow mapping и cascades

Shadow map — depth сцены с позиции света. В lighting pass world position преобразуется light VP matrix; после perspective divide координаты переводятся в [0,1] и сравниваются с сохранённой глубиной.

PCF shadow sampling
float SampleShadow(vec4 lightClip, vec3 normal, vec3 lightDir) {
    vec3 p = lightClip.xyz / lightClip.w;
    p = p * 0.5 + 0.5;
    if (p.z > 1.0) return 1.0;

    float bias = max(0.0005 * (1.0 - dot(normal, lightDir)), 0.00005);
    vec2 texel = 1.0 / textureSize(uShadowMap, 0);
    float visibility = 0.0;
    for (int y = -1; y <= 1; ++y)
        for (int x = -1; x <= 1; ++x)
            visibility += texture(uShadowMap,
                vec3(p.xy + vec2(x,y) * texel, p.z - bias));
    return visibility / 9.0;
}

Directional light для большой камеры требует Cascaded Shadow Maps: разделите view frustum на 3–5 диапазонов, постройте tight orthographic projection для каждого и стабилизируйте её привязкой к shadow texels. Иначе появится shimmering.

HDR environment и Image-Based Lighting

Полный IBL pipeline обычно предвычисляет:

  • Equirectangular HDR → cubemap.
  • Diffuse irradiance cubemap — свёртка низких частот.
  • Prefiltered specular cubemap по mip levels roughness.
  • 2D BRDF integration LUT для split-sum approximation.

В runtime diffuse берётся из irradiance по normal, specular — из prefiltered environment по reflection direction и mip, затем умножается на BRDF LUT. Ambient occlusion обычно влияет на indirect component, но не должен механически затемнять прямой свет.

Framebuffer — набор destinations, а не изображение. Texture attachments удобно читать позже; renderbuffer подходит для transient depth/MSAA, если sampling не нужен.

21. RenderPass

RenderPass фиксирует target, load/clear operations, viewport и callback команд. Это понятный промежуточный шаг перед полноценным render graph.

RenderPass.cs · C#
public sealed record RenderPass(
    string Name,
    RenderTarget Target,
    Vector4? ClearColor,
    bool ClearDepth,
    Action<RenderContext> Execute);

public void ExecutePass(RenderPass pass)
{
    using var marker = _device.PushDebugGroup(pass.Name);
    pass.Target.Bind();
    _device.SetViewport(pass.Target.Width, pass.Target.Height);

    ClearBufferMask mask = 0;
    if (pass.ClearColor is Vector4 color)
    {
        _device.GL.ClearColor(color.X, color.Y, color.Z, color.W);
        mask |= ClearBufferMask.ColorBufferBit;
    }
    if (pass.ClearDepth)
        mask |= ClearBufferMask.DepthBufferBit;
    if (mask != 0)
        _device.GL.Clear(mask);

    pass.Execute(_context);
}

Ping-pong и hazards

Нельзя одновременно sampling texture и писать в ту же область этой texture без специальных механизмов. Выдавайте каждому pass отдельный output или ping-pong пару. Render graph сможет переиспользовать физическую память, когда lifetimes логических ресурсов не пересекаются.

Bloom, exposure и tone mapping

Хороший bloom — не размытие всего кадра. Извлеките яркость мягким threshold, постройте downsample pyramid с фильтрацией, затем upsample-add. Это быстрее большого Gaussian blur и даёт естественный широкий ореол.

Tone mapping fragment shader
vec3 AcesApprox(vec3 x) {
    const float a = 2.51;
    const float b = 0.03;
    const float c = 2.43;
    const float d = 0.59;
    const float e = 0.14;
    return clamp((x * (a * x + b)) / (x * (c * x + d) + e), 0.0, 1.0);
}

void main() {
    vec3 hdr = texture(uScene, vUv).rgb + texture(uBloom, vUv).rgb;
    vec3 exposed = hdr * exp2(uExposure);
    vec3 mapped = AcesApprox(exposed);
    // Если default framebuffer не выполняет sRGB conversion:
    vec3 display = pow(mapped, vec3(1.0 / 2.2));
    oColor = vec4(display, 1.0);
}
Не применяйте gamma дваждыЛибо shader кодирует linear → sRGB, либо включён FramebufferSrgb для sRGB framebuffer. Точно зафиксируйте контракт последнего pass.

Auto exposure строится по log luminance: compute reduction или histogram, percentile clipping, затем temporal adaptation с разной скоростью для входа в свет и темноту.

Compute shaders и barriers

Compute shader работает work groups без rasterizer. Он подходит для particles, culling, image filters, light lists и mip generation. Размер local group выбирайте с учётом алгоритма и GPU; 8×8 или 16×16 — лишь стартовая точка.

Compute dispatch
// GLSL
layout(local_size_x = 8, local_size_y = 8) in;
layout(rgba16f, binding = 0) readonly uniform image2D uInput;
layout(rgba16f, binding = 1) writeonly uniform image2D uOutput;

void main() {
    ivec2 p = ivec2(gl_GlobalInvocationID.xy);
    if (any(greaterThanEqual(p, imageSize(uOutput)))) return;
    imageStore(uOutput, p, imageLoad(uInput, p));
}

// C#
gl.UseProgram(computeProgram);
gl.BindImageTexture(0, input, 0, false, 0, BufferAccessARB.ReadOnly, InternalFormat.Rgba16f);
gl.BindImageTexture(1, output, 0, false, 0, BufferAccessARB.WriteOnly, InternalFormat.Rgba16f);
gl.DispatchCompute((width + 7) / 8, (height + 7) / 8, 1);
gl.MemoryBarrier(MemoryBarrierMask.TextureFetchBarrierBit |
                 MemoryBarrierMask.ShaderImageAccessBarrierBit);

Barrier описывает последующее потребление данных, а не «ожидание вообще». Не используйте AllBarrierBits по привычке. Между invocations одной workgroup доступны shared memory и barrier(); между workgroups глобального барьера внутри одного dispatch нет.

Render graph: зависимости вместо ручного порядка

Render graph получает набор passes. Каждый pass объявляет reads/writes и функцию исполнения. Compiler графа строит порядок, вычисляет lifetime ресурсов, создаёт framebuffer, вставляет barriers и может alias-ить временные textures.

Желаемый API
TextureHandle hdr = graph.CreateTexture("HDR",
    new TextureDesc(Size.Relative(1, 1), Format.Rgba16F));
TextureHandle depth = graph.CreateTexture("Depth",
    new TextureDesc(Size.Relative(1, 1), Format.Depth32F));

graph.AddPass<GeometryData>("Geometry", setup =>
{
    setup.Data.Color = setup.Write(hdr, LoadOp.Clear);
    setup.Data.Depth = setup.Write(depth, LoadOp.Clear);
}, (data, context) =>
{
    renderer.DrawOpaque(context, data.Color, data.Depth);
});

TextureHandle bloom = bloomFeature.Build(graph, hdr);
graph.AddPass<ToneMapData>("Tone map", setup =>
{
    setup.Data.Scene = setup.Read(hdr);
    setup.Data.Bloom = setup.Read(bloom);
    setup.Data.Output = setup.Write(graph.Backbuffer);
}, ExecuteToneMap);

Компиляция графа

  1. Проверить, что каждый read имеет producer или imported resource.
  2. Построить directed edges writer → reader и topological sort.
  3. Удалить passes, результаты которых не ведут к side effect/backbuffer.
  4. Вычислить first/last use каждого transient resource.
  5. Выделить совместимые physical allocations из pool.
  6. Собрать FBO cache и transition/barrier plan.
  7. Исполнить passes с debug groups и GPU timestamps.
Начните прощеПервый render graph может не делать aliasing и автоматические barriers. Сначала получите корректные handles, validation, resize и pass order. Оптимизация памяти — следующий этап.

State cache

Обёртка device может пропускать повторные UseProgram, BindVertexArray, blend/depth changes. Но cache должен быть единственным владельцем state; произвольные raw GL-вызовы снаружи сделают его ложным. В debug режиме полезно уметь invalidation/validation.

Производительность без гадания

CPU frame time и GPU frame time независимы. VSync маскирует bottleneck. Измеряйте passes timestamp queries, а не Stopwatch вокруг draw call: команды асинхронны.

  • Используйте RenderDoc для одного кадра: targets, pipeline state, textures, mesh.
  • Добавьте GPU timestamp query pool с задержкой чтения 2–4 кадра.
  • Считайте draw calls, triangles, state changes, uploaded bytes.
  • Не вызывайте Finish; не читайте query result сразу.
  • Сортируйте opaque draws по pipeline/material и приблизительно front-to-back.
  • Переиспользуйте buffers; избегайте managed allocations в render loop.

Persistent mapped ring buffer

Для частых uploads выделите большой buffer с persistent/coherent mapping, делите на frame regions и защищайте повторное использование fences. Это снижает driver overhead, но требует строгого allocator. Более простой первый шаг — orphaning или несколько rotating buffers.

Lifetime, контекст и IDisposable

GL handle нужно удалить до уничтожения контекста и на потоке, где контекст активен. Финализатор непригоден для прямого Delete*: неизвестны поток, момент и существование контекста.

Owning resource pattern
public sealed class GpuBuffer : IDisposable
{
    private GL? _gl;
    public uint Handle { get; private set; }

    public GpuBuffer(GL gl, nuint size)
    {
        _gl = gl;
        Handle = gl.CreateBuffer();
        gl.NamedBufferStorage(Handle, size, null, BufferStorageMask.DynamicStorageBit);
    }

    public void Dispose()
    {
        GL? gl = Interlocked.Exchange(ref _gl, null);
        if (gl is null) return;
        gl.DeleteBuffer(Handle);
        Handle = 0;
    }
}

Для сложного движка Dispose может помещать handle в deletion queue render thread. Контейнер зависимостей должен уничтожать rendering scope до окна/контекста. Не смешивайте ручное владение и DI ownership одного объекта.

Порядок разработки собственного renderer

  1. Foundation: окно, debug callback, resize, shader compile, owning resources.
  2. Geometry: indexed mesh, camera, depth/culling, texture, glTF import.
  3. Scene extraction: render items, frustum culling, sorting, material contracts.
  4. Lighting: linear HDR, PBR, point/directional lights, shadow map.
  5. Frame resources: UBO/SSBO, transient targets, resize-safe pool.
  6. Post: bloom pyramid, exposure, tone map, FXAA/TAA.
  7. Scale: instancing, indirect draws, clustered lights, compute culling.
  8. Graph: declarative passes, validation, profiling, resource aliasing.
Критерий готовности этапаКаждый шаг должен иметь debug labels, корректный resize, предсказуемое владение ресурсами, capture в RenderDoc и измерение времени. Красивый кадр без диагностики — ещё не система.

Чек-лист типичного чёрного экрана

  • Есть активный контекст, callback не сообщает ошибку.
  • Viewport ненулевой и соответствует текущему framebuffer.
  • Program успешно linked и действительно выбран.
  • VAO выбран, attributes enabled, stride/offset верны.
  • Framebuffer complete, draw buffers настроены.
  • Depth/culling не отбрасывают всю геометрию.
  • Матрицы дают clip coordinates с корректным W.
  • Texture completeness, unit и sampler binding согласованы.
  • После compute стоит нужный memory barrier.
